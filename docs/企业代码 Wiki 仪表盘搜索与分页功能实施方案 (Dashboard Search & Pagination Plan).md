# 企业代码 Wiki 仪表盘搜索与分页功能实施方案 (Dashboard Search & Pagination Plan)

> **实施目标：** 解决代码仓库数量剧增时，首页仪表盘卡片瀑布流冗长、查找困难、以及并发发起大量构建状态请求导致性能损耗的问题。在不修改后端核心协议的前提下，为仪表盘 (`index.html`) 增加**多维即时检索、按需分页、状态筛选**以及**按页懒加载构建状态**等关键能力。

---

## 一、核心痛点与架构优化点

| 现状痛点 | 优化后设计 |
|:---|:---|
| **缺乏检索能力**：几十/上百个仓库只能靠人工滚动查找 | **即时搜索框 + 状态筛选器**：支持按仓库名称/ID 拼音及英文模糊搜索，配合状态下拉单快速过滤 |
| **首屏全量渲染**：所有仓库一次性生成 DOM，页面冗长 | **3 列卡片按需分页**：每页默认 9 或 12 个（完美匹配每行 3 列），支持动态切换分页大小 |
| **网络请求风暴 (严重性能隐患)**：首屏对每个仓库均并发请求 `/api/build/status`（100 个仓库会发 100 次 HTTP 请求） | **按页延迟拉取 + 内存缓存**：仅对当前展示页的仓库拉取状态，翻页优先复用内存缓存，网络并发降低 80%~90% |
| **视觉体验**：无统一分页组件 | **现代暗黑风分页条**：集成上一页、下一页、数字页码跳转与记录统计，完全契合现有 Portal 视觉风格 |

## 二、UI 交互设计与功能规范

### 1. 搜索与筛选工具栏 (Toolbar)
在仪表盘标题与卡片网格之间，新增居中/两侧对齐的工具栏：

```
+-----------------------------------------------------------------------------------------------------------------+
| 企业代码 Wiki 仪表盘                                                                                             |
| 在线查阅各代码仓库的生成 Wiki 或启动 AI 深度问答                                                                  |
+-----------------------------------------------------------------------------------------------------------------+
| [ 🔍 搜索仓库名称或标识... ]   [ 状态: 全部 ▼ ]   [ 每页 9 条 ▼ ]            共 20 个仓库 (当前匹配 20 个)  [🔄 刷新] |
+-----------------------------------------------------------------------------------------------------------------+
|  [ Repo Card 1 ]              [ Repo Card 2 ]              [ Repo Card 3 ]                                      |
|  [ Repo Card 4 ]              [ Repo Card 5 ]              [ Repo Card 6 ]                                      |
|  [ Repo Card 7 ]              [ Repo Card 8 ]              [ Repo Card 9 ]                                      |
+-----------------------------------------------------------------------------------------------------------------+
|                               [ < 上一页 ]  [ 1 ]  [ 2 ]  [ 3 ]  [ 下一页 > ]                                    |
+-----------------------------------------------------------------------------------------------------------------+
```

- **搜索输入框 (`#repoSearchInput`)**：
  - 占位符：`搜索仓库名称或标识（如 order-service）...`
  - 交互：支持 `input` 事件实时防抖（Debounce 250ms）或清空立即刷新；
  - 逻辑：对 `name` 和 `id` 不区分大小写模糊匹配。
- **构建状态筛选 (`#statusFilter`)**：
  - 选项：`全部状态` / `已构建完成` / `增量构建中` / `未构建或失败`。
- **每页容量选择 (`#pageSizeSelect`)**：
  - 选项：`9 条/页`、`18 条/页`、`36 条/页`、`全部`。
- **统计信息 (`#filterStats`)**：
  - 动态显示：`共 X 个仓库，匹配 Y 个`。

---

### 2. 现代分页组件设计 (Pagination Controls)
- 放置在卡片列表底部居中；
- 包含：`上一页`、页码按钮（如 `1`、`2`、`3`，当前页高亮）、`下一页`；
- 当总页数 <= 1 时自动隐藏分页器；
- 翻页操作平滑滚动至列表顶端。

### Task 3: 仪表盘核心交互逻辑重构 (`deploy/unit2-portal/public/js/dashboard.js`)

#### 1. 状态管理
```javascript
let allRepos = [];          // 全量仓库列表
let filteredRepos = [];     // 经过搜索与筛选后的仓库列表
let currentPage = 1;        // 当前页码
let pageSize = 9;           // 每页显示卡片数
let buildStatusCache = {};  // 缓存：repoId -> 最新构建状态对象
let searchQuery = '';       // 当前搜索关键词
let selectedStatus = 'all'; // 状态筛选值
```

#### 2. 核心函数流程
1. **`loadRepos()`**：
   - 仅一次性拉取 `allRepos = await API.getRepos()`；
   - 触发 `applyFiltersAndRender(resetPage = true)`。
2. **`applyFiltersAndRender(resetPage)`**：
   - 根据 `searchQuery` 和 `selectedStatus` 过滤得到 `filteredRepos`；
   - 计算总页数 `totalPages = Math.ceil(filteredRepos.length / pageSize)`；
   - 若 `resetPage` 则重置 `currentPage = 1`；
   - 切片获取当前页数据：`pageRepos = filteredRepos.slice((currentPage-1)*pageSize, currentPage*pageSize)`；
   - **关键性能优化**：仅对 `pageRepos` 中未缓存的仓库并发请求 `API.getBuildHistory(r.id)`，并写入 `buildStatusCache`；
   - 渲染当前页卡片；
   - 渲染分页条按钮。
3. **事件绑定**：
   - 搜索框输入防抖监听；
   - 下拉框变更监听；
   - 分页按钮点击切换监听。
